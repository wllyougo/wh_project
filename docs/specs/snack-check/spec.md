# 낱개 간식 확인

앱의 전제는 [PRODUCT.md](../../../PRODUCT.md)에 있고, 용어는 [GLOSSARY.md](../../../GLOSSARY.md)를 따른다. 이 스펙은 그중 "사진 한 장으로 낱개 간식의 원재료명과 알레르기 표시를 확인한다"는 첫 번째 작업 단위의 계약이다.

## 사용자에게 달라지는 것

보호자가 정체를 모르는 낱개 간식의 사진을 올리면, 앱이 **후보** 제품 최대 3개와 각 후보의 **원문 페이지**를 바로 보여 준다. 앱이 원문 페이지를 읽을 수 있으면 원재료명과 **알레르기 표시란**을 보여 주고, 보호자가 미리 등록한 **알레르기 설정** 항목이 있는지 없는지를 근거와 함께 알려 준다. 읽지 못하면 그 사실과 원문 페이지 링크를 보여 준다. 보호자는 여러 번의 검색 대신 한 번의 업로드로 판단 근거에 닿고, 아이에게 먹어도 되는지는 보호자가 직접 말해준다.

## 승인된 범위

1. **알레르기 설정**: 보호자가 아이의 알레르기 항목을 식품 알레르기 표시 대상 항목 중에서 여러 개 고른다. 설정은 로그인 없이 이 기기에 저장된다.
2. **사진 입력**: 파일 선택, 이미지 붙여넣기, 모바일 카메라 촬영(파일 선택 입력에서 카메라가 열리는 방식)으로 사진 한 장을 올린다.
3. **후보 제시**: 사진으로 후보를 최대 3개 찾아 드롭다운(펼침 목록)으로 보여 준다. 후보마다 제품명, 알 수 있는 경우 제조사와 맛, 대표 이미지, 원문 페이지 링크를 표시한다.
4. **후보별 결과**: 후보를 펼치면 원재료명과 알레르기 표시란을 보여 주고, 설정 항목의 포함 여부를 알린다. 자동 읽기에 실패한 후보는 읽지 못했다는 안내와 원문 페이지 링크만 보여 준다.
5. **확인 불가**: 후보를 찾지 못한 경우를 보여 준다.
6. **확인 기록**: 확인할 때마다 한 건씩 기기에 남기고, 목록에서 다시 열어 볼 수 있다.
7. 위 흐름의 로딩, 오류, 빈 상태, 모바일 폭에서의 배치.

## 관찰 가능한 수용 기준

**알레르기 설정**
- 설정에서 항목을 고르고 앱을 다시 열어도 같은 항목이 선택되어 있다.
- 설정이 비어 있으면 첫 확인 전에 설정을 안내한다. 안내를 건너뛰고 확인하는 것도 가능하며, 이때 결과는 설정 항목 강조 없이 원재료명과 알레르기 표시란만 보여 준다.

**사진 입력**
- 파일 선택, 붙여넣기(Ctrl+V), 모바일의 카메라 입력으로 사진을 올릴 수 있고, 올린 직후 추가 버튼 없이 후보 찾기가 시작된다.
- 이미지가 아닌 파일이나 허용 크기를 넘는 파일은 이유를 알려 주고 아무것도 시작하지 않는다.
- 찾는 동안에는 진행 중임을 알리는 상태가 보인다.

**후보 제시**
- 후보는 최대 3개이고, 첫 후보가 펼쳐진 상태로 나온다. 다른 후보는 눌러서 바로 펼쳐 볼 수 있다.
- 같은 이름의 제품이 제조사별로 여러 개면 각각 별도 후보로 나오며, 제조사나 맛이 눈에 보이는 위치에 표시된다.
- 후보를 하나로 단정하는 문구("이 제품입니다" 등)를 쓰지 않는다.

**후보별 결과 (자동 읽기에 성공한 경우)**
- 원재료명과 알레르기 표시란의 내용이 원문 페이지의 내용과 함께 보이고, 보이는 곳에서 원문 페이지로 이동할 수 있다.
- 설정한 항목마다 아래 중 하나로 알린다. 근거가 되는 위치(알레르기 표시란, 원재료명)가 문구에 함께 나온다.
  - "알레르기 표시에 우유가 있습니다"
  - "원재료명에 우유가 있습니다" (알레르기 표시란에는 없는데 원재료명에서 발견된 경우)
  - "알레르기 표시와 원재료명에 우유가 없습니다"
- 알레르기 표시란이 원문에 없으면 "이 제품 정보에는 알레르기 표시란이 없습니다. 원재료명만 확인하세요"를 함께 알린다. 이 경우에도 원재료명에서 설정 항목을 찾아 위 문구로 알린다.
- 앱은 "먹어도 됩니다", "안전합니다", "위험합니다" 같은 판정 문구를 어디에도 쓰지 않는다.

**후보별 결과 (자동 읽기에 실패한 경우)**
- "자동으로 읽지 못했습니다"와 원문 페이지 링크를 보여 주고, 설정 항목의 포함 여부는 알리지 않는다.

**확인 불가**
- 후보가 하나도 없으면 "확인 불가"와 이유를 알려 주고, 같은 화면에서 다른 사진을 다시 올릴 수 있다.
- 사진은 올렸지만 외부 서비스 오류로 후보를 못 받은 경우도 확인 불가와 구분되는 오류 문구로 알리고, 다시 시도할 수 있다.

**확인 기록**
- 확인이 끝날 때마다 사진, 후보 목록, 결과, 확인 날짜가 한 건으로 남고, 별도의 저장 조작은 필요 없다.
- 기록 목록에서 한 건을 열면 그때의 결과를 다시 볼 수 있다. 다시 열 때 외부 서비스를 새로 부르지 않는다.
- 기록은 이 기기에만 있고, 다른 기기나 다른 사람에게는 보이지 않는다.

## 확정된 제약과 이유

- **근거는 포장 표시사항을 옮긴 원문 페이지다.** 식약처 DB는 근거로 쓰지 않는다. 결정과 이유는 [allergen-source](../../decisions/allergen-source.md)에 있다.
- **판정하지 않고 표시된 내용만 보여 준다.** 판단은 보호자가 하며, 앱이 안전을 보증하는 것처럼 읽히지 않게 한다.
- **"혼입 가능" 문구는 다루지 않는다.** 보호자가 이 앱에서 중요하게 보는 정보가 아니라고 정했다.
- **글씨를 직접 읽지 못한 정보를 읽은 것처럼 보여 주지 않는다.** 읽기 오류가 곧 알레르기 오표시가 되기 때문이다.
- UI는 [ui-composition](../../decisions/ui-composition.md)의 기준을 따른다.

## 가정 (정하지 않고 둔 기본값, 바꿀 수 있음)

- 알레르기 설정과 확인 기록은 로그인 없이 기기 안에만 저장한다.
- 설정 항목과 같은 뜻의 다른 표기(계란=달걀·알류, 우유=분유·유청 등)는 같은 항목으로 본다. 표기 목록은 구현하면서 정하고, 놓치는 표기가 있을 수 있다.
- 후보 순서는 이미지 검색이 준 순위를 따른다.
- 사진은 후보를 찾기 위해 외부 이미지 검색 서비스에 일시적으로 전달된다. 이 사실을 업로드 화면에서 알린다.
- 확인 한 건의 기록에는 보호자가 펼쳐 본 후보와 상관없이 그때 제시된 후보 전체가 남는다.

## 범위 밖과 이유

- **식단 준비**: 이 앱의 범위인지 아직 정해지지 않았다([PRODUCT.md](../../../PRODUCT.md)의 미해결).
- **제품명이나 바코드를 직접 입력해 확인하는 입력 방식**: 사진으로 후보를 못 찾았을 때의 대안으로 논의됐지만 이번 범위로 정해지지 않았다.
- **로그인, 계정, 여러 아이 관리, 기기 간 기록 동기화**: 사용자가 "내 아이 한 명 기준"이라고 정했다.
- **교차오염("혼입 가능") 안내**: 위 제약 참고.
- **원재료·알레르기 판정 문구**: 위 제약 참고.

## 미뤄 둔 결정

- **자동 읽기의 약속 수준** (임시): 지금은 읽기에 성공하면 설정 항목을 강조하고, 실패하면 원문 페이지 링크로 대신한다. PRODUCT.md의 "추가 조작 없이 원재료명과 알레르기 표시가 바로 보인다"는 **읽기에 성공한 후보에서만** 지켜지는 임시 상태다. 읽기가 여러 제품에서 안정적으로 동작한다는 근거가 모이면 약속을 원래대로 되돌리는 결정으로 교체한다.
- **확인 기록의 구체적인 쓰임**: 다시 보고 싶은 순간이 있다는 것만 확인됐다. 지금은 "확인마다 자동으로 남기고 목록에서 다시 열기"까지만 만든다(임시). 쓰임이 정해지면 교체한다.
- **이미지 식별과 원문 읽기에 쓸 외부 서비스**: 이미지 검색 서비스(SerpApi의 Google Lens가 시험을 통과함)와 원문 읽기에 쓸 방식은 구현 단계에서 접근 가능한 것으로 정한다. 사내망에서 막히는 경우의 대안은 그때 정한다.

## 남은 위험

- **식별 정확도**: 사진 3장 시험에서 정답이 모두 첫 번째였지만 표본이 작다. 글씨가 없는 낱개 간식과 같은 이름의 여러 제조사 제품이 섞이면 틀릴 수 있다.
- **자동 읽기 성공률은 모른다**: 쇼핑몰·제조사 페이지 4곳으로 한 시험에서는 단순 요청으로 원재료 텍스트를 얻지 못한 곳이 많았다. 읽기 성공 비율이 낮으면 대부분의 결과가 링크로만 나와 PRODUCT.md의 약속이 지켜지지 않는다.
- **읽기 오류의 위험**: 잘못 읽은 결과를 보여 주면 알레르기 오표시가 된다. 원문을 함께 보여 주는 것이 유일한 안전장치다.
- **동의어 누락**: 설정 항목과 같은 뜻의 표기를 놓치면 "없습니다"로 잘못 알릴 수 있다.
- **외부 접근**: 판매처가 서버의 접근을 막거나 약관이 자동 수집을 막을 수 있다.
- **개발 환경**: 사내망에서 외부 이미지 검색과 모델 호출이 막히면 개발 단계에서 시험할 수 없다.

- [PRODUCT.md](../../../PRODUCT.md): 이 작업의 앱 수준 전제.
- [allergen-source](../../decisions/allergen-source.md): 알레르기 정보의 근거를 원문 페이지로 한다는 결정. 결과 화면이 무엇을 근거로 삼는지를 정한다.
- [ui-composition](../../decisions/ui-composition.md): 화면 구성과 컴포넌트 선택의 기준.
- 승인된 프로토타입은 없다. 화면 구성은 위 수용 기준을 따른다.
